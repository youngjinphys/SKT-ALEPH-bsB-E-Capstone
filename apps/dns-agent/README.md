# DNS 에이전트

김다영님의 [제출본](https://app.notion.com/p/4045db6797f081b8a83ff33efa2235fe)의
입력 검증·dnsmasq 설정 생성·실패 복원 의도를 유지했습니다.
기본은 격리 실험이고, **별도 관리 명령으로 실제 Linux 시스템의 LAN DNS 서비스를 설치**할 수 있습니다. 팀의 운영 설계 승인이나 운영망 가용성이 검증됐다는 의미는 아닙니다.

## 작동 범위

- Python 3.11+, Linux. DNS 에이전트 프로세스는 일반 사용자로 실행하며 직접 `sudo` 실행을 거부합니다.
- 기본 `127.0.0.1:35353` 실습 모드는 시스템 설정을 변경하지 않습니다. 실제 LAN 모드는 [시스템 관리자 설치 도구](../../infra/edge/README.md)가 전용 systemd 서비스와 nftables ACL을 설치하며 서비스에는 53번 바인딩 능력만 부여합니다. `/etc/resolv.conf`나 DHCP는 자동 변경하지 않습니다.
- `BLOCK + approved=true + 유효기간 내`인 SUBTREE 규칙만 `address=/domain/`으로 생성합니다.
- `WARN`은 차단하지 않는 주의 상태이고 `ALLOW`는 해당 목록에서 차단하지 않는 상태입니다. 경고 페이지를 자동으로 띄우거나 악성 여부를 보증하지 않습니다.
- `EXACT`는 지원하지 않아 오류 처리합니다. 상위 BLOCK과 하위 ALLOW/WARN 등의 충돌도 거부합니다.
- 기본 입력은 `.test`만 허용합니다. `--allow-public-domains`는 명시적인 실험 범위 확대 옵션이지 운영 승인이나 공용 도메인 과차단 방지 기능이 아닙니다.

## 읽기 전용 명령

저장소 루트에서:

```sh
export PYTHONPATH="$PWD/apps/dns-agent/src"
python3 -m dns_agent example > /tmp/capstone-policy.json
python3 -m dns_agent validate /tmp/capstone-policy.json
python3 -m dns_agent render /tmp/capstone-policy.json --upstream 127.0.0.1 --upstream-port 35453
```

`example`은 유효기간 1시간의 합성 데이터를 출력합니다. `validate`는 형식을 검사하고,
`render`는 설정을 표준 출력에만 씁니다. 위 예시의 35453번 업스트림은 별도로 준비해야 하며 자동 생성되지 않습니다.
날짜가 고정된 저장소 예제는 형식 참고용입니다. 실제 실행에는 새 시각의 예제를 생성하세요.

## 명시적인 격리 실행

일반 사용자 소유의 실습 VM에서 `dnsmasq-base`와 `dnsutils`를 설치합니다.
패키지 설치는 VM 관리 작업이며 이 프로그램이 대신 수행하지 않습니다.
신뢰할 재귀 DNS의 IP를 지정하거나 통합 테스트의 로컬 fixture를 사용합니다.

```sh
# UPSTREAM_IP는 담당자가 검증한 DNS 주소로 직접 설정합니다.
export UPSTREAM_IP=127.0.0.1
python3 -m dns_agent run /tmp/capstone-policy.json \
  --state-dir "$HOME/.local/state/aleph-dns-lab" \
  --upstream "$UPSTREAM_IP" --upstream-port 35453
```

이는 준비된 로컬 업스트림을 가정한 예시입니다. 실제 업스트림이 53번을 쓰면
`--upstream-port 53`으로 명시합니다. 자기 자신의 리스너를 업스트림으로 지정하면 거부합니다.
다른 터미널에서 `dig @127.0.0.1 -p 35353 blocked.test A` 등으로 직접 질의합니다.
고포트 실험을 OS의 기본 DNS 설정이나 LAN 배포가 완료된 것으로 취급하지 않습니다. LAN IP의 53번 포트에서 정상 서비스를 제공하려면 [별도 시스템 설치 절차](../../infra/edge/README.md)를 수행해야 합니다.

## 안전한 갱신과 실패 처리

1. JSON 중복 키, 비정상 숫자, 입력·정규화 후 각각 1 MiB 한도·개수(10,000), 도메인·범위·승인·시각을 검증합니다.
2. 이전에 적용한 발행시각보다 오래된 파일, 같은 시각에 다른 내용을 가진 파일은 거부합니다.
3. 사용자 소유의 `0700` 상태 디렉터리와 배타 잠금을 사용합니다. 심볼릭 링크 입력·상태 파일은 거부합니다. 저장 정책과 설정의 해시 및 상태 필드를 점검하고, 손상된 복구 저널은 활성 설정을 덮기 전에 거부합니다.
4. 완전한 후보 설정을 `dnsmasq --test`로 검사한 뒤 복구 저널을 저장합니다.
5. 소유한 프로세스만 필요 시 교체하고 **UDP/TCP, A/AAAA 로컬 건강 답변의 이름·유형·IP·패킷 길이와 차단 카나리아**를 검사한 뒤 상태를 기록합니다. 실행 중에는 최대 약 5초 간격으로 실제 로컬 A/AAAA와 차단 카나리아를 재확인해 응답하지 않는 프로세스를 복구 시도합니다. 정책 메타데이터만 변경되고 실제 DNS 설정이 동일하면 리스너를 재시작하지 않습니다. 후보 설정·복구 저널 기록에 실패해도 이전 정상 리스너를 유지하고 해당 갱신만 거부합니다.
6. 실패하면 이전 설정·메타데이터·프로세스를 복구합니다. 복구도 실패하면 서비스를 중단하고 저널을 남깁니다.
7. 소스 파일이 손상되어도 기존 정책의 유효기간을 무한 연장하지 않습니다. 만료 규칙은 다음 점검에 제거하며, 안전한 갱신 실패 시 오래된 차단을 계속 서비스하지 않습니다.

재시작 시 정책 파일이 없거나 유효하지 않아도 복구 저널과 저장된 상태를 먼저 검증하고,
신뢰할 수 있는 이전 정책이 있으면 현재 시각에 맞춰 유효한 차단만 다시 적용합니다.
이전 정책이 없으면 시작하지 않으며, 손상된 저널이나 상태는 자동 복구하지 않고 오류로 남깁니다.

발행시각과 해시는 재전송·내용 충돌을 식별하기 위한 값이지 발행자 인증이 아닙니다.
`approved` 역시 JSON 필드일 뿐 권한 증명이 아닙니다. 이 구현은 **동일 사용자/관리자가 검토한 로컬 파일**을 신뢰 입력으로 가정합니다.
원격 갱신에는 인증, 서명 키 관리, 신뢰할 시계, 배포 권한 검토가 추가로 필요합니다.

폴링 기본 1초(허용 0.1–10초)에 검사·재기동 시간이 더해집니다. 0초 철회, 무중단 전환,
전원 장애·파일시스템 오류에 대한 완전한 복구, 재시작을 넘나드는 시계 역행 방어는 보장하지 않습니다.
실행 중 시계 역행뿐 아니라 **마지막으로 저장한 적용시각 이전으로 재시작 후 시계가 역행하는 경우**도 만료 차단을 되살리지 않습니다. 단, 마지막 기록 이후 시스템 종료 중 경과한 시간을 신뢰할 외부 시계 없이 증명할 수는 없습니다. Linux 부모 종료 신호로 고아 리스너를 정리합니다.
상태 확인은 **소유한 로컬 리스너의 대표 응답**을 확인하며 외부 업스트림 전체의 정상 여부, 모든 차단 규칙, 클라이언트 가용성까지 보증하지 않습니다. 오류가 난 갱신이 유효기간을 지난 차단 규칙을 남기게 되는 경우에는 오래된 차단을 계속 서비스하지 않고 종료합니다.

## 테스트

```sh
PYTHONPATH=apps/dns-agent/src python3 -m unittest discover -s apps/dns-agent/tests -v
# 실제 바이너리 없는 경우를 실패로 처리하고 싶은 CI/실습 환경:
REQUIRE_DNSMASQ=1 PYTHONPATH=apps/dns-agent/src \
  python3 -m unittest discover -s apps/dns-agent/tests -v
```

`test_integration.py`는 일반 사용자로 실제 dnsmasq 두 개와 독립 `dig`를 실행합니다.
정책 적용 전의 `.test` 이름에 정상 A/AAAA를 주는 **통제 업스트림**을 만들므로
원래 NXDOMAIN인 도메인을 차단 성공으로 오판하지 않습니다. UDP/TCP, 하위 이름,
비대상·WARN 통과, 철회·만료, 부모 종료와 정책 파일 부재·손상 시 재시작 복구를 시험합니다.
인터넷·운영 DNS 변경은 필요 없습니다.
