# 캡스톤 발표 데이터

- `slides.index.json`: 23개의 저작 데이터. 공개 발표 14개와 아카이브 9개를 모두 보존합니다.
- `sequence.json`: 표지 포함 14장, 1,200초의 단일 발표 순서입니다. 표지는 발표 전 대기 화면으로 0초입니다.
- `slides/*.json`: 제목·요점·근거·발표자 노트. 활성 슬라이드의 `seconds`는 sequence와 같습니다.
- `diagrams.json`: 설명용 DNS·정책·HTTP 흐름. 버튼 조작이 운영 DNS를 변경하지 않습니다.
- `dns-latency.json`: 고정 원시 CSV, 측정 조건, 선형보간 p50/p95, 줄바꿈별 해시를 포함합니다.
- `sources.json`: 외부 공식 근거, 현재 구현, 과거 기능 실험, Pi 실측을 구별합니다.
- `slide.schema.json`: 발표 데이터 필드의 계약입니다.

## 단일 서사

문제·보호 역할·선례 → DNS 응답·후보 승인·서명·철회 → 합성 기능 실험·Pi 전달 지연 → HTTPS 사유 안내·리졸버 경로 → 추가 효과와 운영 품질의 검증입니다.

DNS·정책 코어 근거는 `6bf8ccac`이며 통합 `9e84275`에서 같은 코어와 클라우드 관제 차분을 추가 확인했습니다. 240건 기능 실험은 `397df3f4` 기록, Pi 측정 당시 코드는 `9187102d`입니다. 이 세 기준점을 하나의 최신 종단 간 실증으로 합쳐 설명하지 않습니다.

Pi의 제품 :53은 로컬 응답 캐시를 끄고, 측정 당시 활성 차단 규칙이 없었습니다. 임시 :55353 캐시 히트는 별도 실험입니다. 그래프의 분위수 차이는 각 분포 요약값의 차이로서 정책의 인과적 비용과 구분합니다.

## 원고를 수정할 때

활성 슬라이드의 `notes`를 고친 뒤 `docs/presentation/final-20min-scenario.md`의 같은 화면 본문을 동일하게 반영합니다. 시간이나 제목을 고치면 sequence·원고 표·화면 제목도 함께 갱신합니다. `npm run content:check`는 순서·시간·노트 본문과 출처·아카이브 관계를 검사합니다.

목차는 하나만 유지하며 방향키 슬라이드 이동이나 화면 타이머를 다시 추가하지 않습니다. 질의응답 자료는 최종 원고의 발표자 참고 절에 있습니다.
