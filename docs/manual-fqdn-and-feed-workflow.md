# ALEPH DNS: 수동 FQDN과 OpenPhish / Google Safe Browsing

## 관제 화면 운영 흐름

기존 `/dashboard`의 DNS 정책 초안에서 수동으로 FQDN을 등록·갱신·해제할
수 있습니다. 등록에는 검토자(2~80자), 근거(15~400자), 만료시각(5분
초과~7일), SUBTREE 영향 동의가 필요합니다. 차단 대상 도메인과 모든
하위 도메인까지 포함되는 것을 반드시 검토하세요. URL 경로·와일드카드·
IP 주소는 등록 대상이 아닙니다. 국제화 도메인은 ACE/IDNA 변환 후 별도
검토가 필요합니다.

독립 위험도 v0.8 EXACT 제안 설정과 혼동하면 안 됩니다. 수동 블랙리스트
등록은 미서명 정책 초안의 후보만 변경합니다. 이전에 서명·게시된 DNS
정책이나 실제 차단 상태는 바로 바뀌지 않습니다. 해제도 새 정책 서명·
게시와 노드 적용을 거쳐야 DNS에 반영됩니다.

OpenPhish 공개 URL 피드 → Google Safe Browsing v5 URL 검증 → 검증 자료
미리보기 → 명시적 가져오기 → 도메인/SUBTREE 승인 → 미서명 정책 초안
순서로 처리합니다. 외부 응답의 URL을 방문하지 않으며, GSB 결과만으로
자동 승인·자동 차단하지 않습니다. 검증 자료를 새로 가져오면 이전
검토 기록은 비공개 아카이브에 보존하고 새 자료는 미승인으로 시작합니다.

수동 승인과 검증된 외부 승인을 결합할 때 초안은 전체 교체 스냅샷이며,
**가장 먼저 만료되는 개별 규칙을 초과해 유효하지 않습니다.**
서명은 독립 Ed25519 키로 별도 수행해야 하며, 정책 서버 게시·DNS 노드
다운로드·적용 영수증은 각각 별개 검증 단계입니다.

### 등록 경계, 철회와 근거 보존

- 공용 접미사와 그 상위 공유 경계는 SUBTREE 대상으로 등록할 수 없습니다.
  저장소에 고정한 전체 Public Suffix List(ICANN·PRIVATE, wildcard·exception)를
  오프라인으로 검사하며 기존 보호 도메인 제한도 유지합니다. 런타임 목록
  다운로드는 없습니다. snapshot 변경은 `public_suffix.py`의 upstream commit과
  SHA-256을 함께 검토해 갱신해야 합니다. 데이터는 MPL-2.0입니다.
- 이전 버전에서 등록된 안전 경계 위반 항목은 조회·해제할 수 있으나
  유효한 동안 새 초안 생성을 차단합니다. 자동 삭제나 기존 게시 변경은 없습니다.
- 만료된 GSB 승인으로 생성이 막히면 화면에 표시된 제외 목록과 영향을
  별도로 확인하세요. 서버는 정확한 승인 ID와 최신 두 source revision을
  확인하고 만료 항목만 제외합니다. 원본 승인·검토 기록은 변경하지 않으며,
  손상·미래 시각·증거 불일치·보호 경계 오류는 계속 거부합니다.
- 마지막 규칙을 해제한 뒤에는 **빈 전체 교체 확인**이 추가로 필요합니다.
  `rules=[]`, 유효기간 15분의 미서명 초안만 생성합니다. 기존 정책 전체의
  차단 철회가 가능하므로 독립 서명자의 empty 확인과 게시자의 withdrawal
  확인은 그대로 필요합니다. 체크박스 확인만으로 DNS가 변경되지는 않습니다.
- 수동 기록 원문은 비공개 `manual-evidence/<sha256>.json`에 보존됩니다.
  수정·해제 전에 이전 원문을 보존하며, 초안의 manual evidence 해시로 검증할
  수 있습니다. `draft-evidence/`는 결합 초안의 원본 source 해시 연결과
  명시적 제외 내역을 보존합니다. 둘 다 cloud CAS snapshot에 포함됩니다.
  저장 실패·해시 충돌·용량 한도 도달 시 변경은 실패하며 과거 근거를
  자동 삭제하지 않습니다. 이 기록에는 검토자와 판단 근거가 있으므로 비공개로 유지하세요.
  적용 전에 이미 덮어써지거나 삭제된 과거 원문은 복원할 수 없습니다.

## 외부 API 활성화

기존 Vercel 프로젝트 Production에 **서버 전용** 환경변수를 다음과
같이 설정한 경우에만 직접 외부 위협정보 조회가 활성화됩니다.

- `SAFE_BROWSING_API_KEY`: Google Safe Browsing v5 API 키
- `ALEPH_OPENPHISH_SOURCE_ALLOWED=true`: 사용 주체·용도가 OpenPhish의
  이용 조건에 부합함을 독립적으로 확인하고 승인한 경우에만 설정

각 조회 시 OpenPhish 약관, Google에 URL을 전송하는 점, 비상업 이용
제약을 운영자가 별도로 확인해야 합니다. 설정이 없다면 원격 조회는
`NOT_CONFIGURED` 상태로 차단하고 수동 FQDN 등록·검증 파일 가져오기는
유지합니다. API 키를 GitHub·브라우저·스크린샷에 넣지 마세요.

서버는 허용된 공식 HTTPS 출처에만 요청하며 최대 15개 URL을 검증합니다.
Naver 연결 기존 CAS 영속 DB에 수집 예약, 정상 15분·실패 2분 쿨다운,
검증 결과와 아카이브를 저장합니다. 브라우저에는 결과 건수·지문·
시각 등 메타데이터만 표시합니다. API 비밀값이나 원시 피싱 URL은
관제 응답으로 반환하지 않습니다.

프로덕션 성공은 실제 GSB 키 설정과 OpenPhish 이용 권한 확보 이후
별도로 검증해야 합니다. 테스트는 가짜 URL·가짜 GSB 결과를 사용합니다.
