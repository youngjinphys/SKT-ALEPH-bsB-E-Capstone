# 위협 모델과 보안 불변조건

**상태:** 설계 원칙/테스트 계획. 실제 보안 검증 결과가 아닙니다.

## 신뢰 경계
1. 외부 피드·AI 분석값은 비신뢰. 관리자 차단·승인 등 특권 필드를 수집된 데이터가 지정할 수 없도록 합니다.
2. 중앙 서버의 정책과 전송 경로는 로컬 검증 대상. 승인·만료·버전·스키마·정규화 확인 전 정책을 적용하지 않습니다.
3. 로컬 적용기의 설정 변경 권한은 서버의 읽기·정책 생성 권한과 별도입니다. 정책 오류가 재귀 DNS 서비스 전체 장애로 이어지지 않도록 원복합니다.
4. 신고 포털은 비신뢰 사용자 입력을 수집합니다. 신고가 자동 차단 해제 권한을 갖지 않습니다. **현재 정적 UI에서는 서버 전송이 없으며 복사 가능한 초안만 생성**합니다. 실제 신고 API 추가 시 CSRF·스팸·XSS·서버 측 입력 검증과 감사 처리가 필요합니다.
5. 데이터 최소화·보존기간·개별 클라이언트 DNS 로그의 외부 반출 제한을 적용합니다.

## 배제/제약
- HTTPS 인증서 대체, HSTS 우회, TLS MITM 또는 클라이언트 루트 CA 강제 설치
- 비관리 단말의 DoH/DoT/DoQ, VPN, 직접 IP/기존 연결까지 모두 차단한다는 주장
- `dnsmasq /example/` 과차단을 EXACT이라고 설명하거나 IP 방화벽 규칙으로 FQDN을 일대일 대체
- 서명·SHA-256·TLS의 보호 목표 혼동: **해시만으로 악의적 정책 발행자를 인증할 수 없음**
- 실제 악성 URL을 격리 없이 테스트에 사용

## 공개 저장소와 배포 공급망

- 같은 Git 저장소의 소스 접근은 런타임·배포 권한 분리를 제공하지 않습니다. DNS 관리자 자격증명과 원격 서버 배포 키는 서로 다른 제한된 권한·환경으로 보관합니다.
- `.gitignore`는 비밀값을 추적한 뒤의 Git 이력이나 강제 추가 파일을 제거하지 않습니다. 유출 시 키 회수·교체와 공개 기록 처리 절차가 별도로 필요합니다.
- CI의 구조 검사는 보안 테스트·악성 패키지 스캔이 아닙니다. 실제 배포 전 의존성/권한·정책 서명/인증·복구 경로를 추가 검증합니다.

## 기술 검증 목록
EXACT/서브도메인, A/AAAA/CNAME, DNSSEC 및 negative TTL, 정책 적용·철회, stale/변조된 정책, 원복, 성능 p50/p95, 오탐, TLS 오류 및 독립 포털.
