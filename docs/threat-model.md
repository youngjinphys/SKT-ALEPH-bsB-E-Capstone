# 위협 모델과 잔여 위험

## 신뢰 경계

외부 IOC·점수·신고는 비신뢰입니다. 검토된 로컬 정책 파일만 현재 입력으로 사용합니다.
`approved=true`와 SHA-256은 승인자의 신원이나 악성 서버의 무결성을 증명하지 않습니다.
상태 디렉터리·실행 사용자·업스트림 DNS는 관리자가 신뢰할 수 있어야 합니다.

## 방어한 실패

- 개행/지시자 삽입, URL·IP 혼입, JSON 중복 키·정규화 결과 크기 초과·알 수 없는 필드
- 암묵적인 차단 범위 확대, 상하위 규칙 충돌, 미승인/만료 항목의 집행
- 동시 실행, 단순 파일 교체 후 서비스 실패, 중단된 트랜잭션의 불일치·저장 정책/복구 저널의 손상
- 새 정책 준비·저널 쓰기 실패가 기존 정상 DNS를 중단시키는 경로, 살아 있으나 응답이 없는 로컬 프로세스
- 같은 발행시각의 변조 내용 또는 오래된 정책 재적용
- 감독 프로세스 종료 후 남는 리스너, 위험한 root/시스템 DNS 변경

## 캠페인 데이터에 대한 신뢰 경계

추가된 캠페인 카탈로그는 **교육용 합성 `.test` 데이터**입니다. `approved=true`는 통제된 실습의 입력 플래그이며 실제 분석가의 승인, 서명된 정책, IOC의 악성 여부를 입증하지 않습니다. 생성기는 정책을 출력할 뿐 배포·연결·실사용 접속 차단을 실행하지 않습니다. 실제 위협정보로 교체하려면 출처 검증·오탐 이의신청·인증된 발행·회수 경로가 필요합니다.

## 시스템 DNS 배포 시 추가 신뢰 경계

- 전용 `aleph-dns` 사용자, 읽기 전용 설치 소스, 제한된 `CAP_NET_BIND_SERVICE` 권한, `/var/lib/aleph-dns` 상태 디렉터리를 사용합니다. 설치 및 정책 발행은 별도 `sudo` 관리자 작업입니다.
- 자체 `nft inet aleph_dns` 테이블은 승인 인터페이스·클라이언트 CIDR 이외에서 들어오는 IPv4 UDP/TCP 53번 질의를 차단합니다. systemd `IPAddressDeny=any`와 클라이언트 CIDR·업스트림 허용도 추가하지만 실제 cgroup IP 필터 지원 여부는 운영 호스트에서 확인해야 합니다. **기존 방화벽의 다른 테이블을 비우지 않습니다.** 다른 nftables 관리자가 규칙을 삭제하거나 덮어쓰면 ACL이 유지된다는 보장은 없습니다.
- `/24`보다 넓은 클라이언트 IPv4 대역과 공인 인터페이스 직접 노출은 기본 거부합니다.
- 설치 당시 root 관리 소스 경로/해시를 보관하고 정책 게시·제거에서 내용 불일치를 검사합니다. 실패 복구는 예상 밖 하위 파일·서비스 상태를 자동 삭제하지 않습니다. 이는 소스의 발행자 인증이나 다른 root 권한 관리자의 모든 동시 조작을 방어하지 못합니다.
- 설치별 식별자와 테이블 전체 구조가 일치해야 재사용·제거합니다. 삭제는 검증한 핸들과 규칙셋 세대번호를 커널 트랜잭션에 지정하고, 해당 기능이 지원되지 않으면 거부합니다. 부분 설치 실패의 잔여 설정과 기존 nft 테이블 충돌을 검사하며, 소유권이 불확실하면 복구 자료를 보존합니다. 정책 게시 성공과 실제 수락은 다르므로 발행 순서·실행 에이전트의 SHA 확인을 요구합니다. 제거 시 정책/상태를 백업합니다. 롤백 자체가 실패하면 운영자 개입이 필요합니다. IPv6 DNS, 원격 지사, 동적 IP 주소, 기존 DNS 서비스·DHCP 설정은 별도 관리·검증 대상입니다.

## 아직 보장하지 않는 것

| 위험 | 처리/한계 |
| --- | --- |
| EXACT 차단 | 이 dnsmasq 백엔드는 지원하지 않아 입력 거부 |
| CNAME·HTTPS/SVCB 응답의 다른 이름/주소 | 요청 QNAME 밖의 응답 체인 검사는 보장하지 않음 |
| DoH/DoT/DoQ·VPN·직접 IP·기존 연결 | 이 리졸버를 우회하는 통신은 보호 대상 밖 |
| DNSSEC | 로컬 재작성은 권한 서버 서명과 다름. 운영 정책·검증 클라이언트 별도 시험 필요 |
| 공유 호스팅·상위 도메인 차단 | 정상 하위 서비스 피해 가능. SUBTREE 승인 범위 검토 필요 |
| 정책 만료 | 차단을 제거해 가용성을 우선하는 실험 선택. 갱신 중단 시 보호 약화 명시 |
| 동시 갱신 중 가용성 | 재시작 구간의 질의 손실 가능. 무중단이라고 주장하지 않음 |
| 로컬 건강검사 | 간격 기반 A/AAAA·대표 BLOCK 응답 확인. 모든 규칙·외부 업스트림·사용자 경로는 검증하지 않음 |
| 디스크 장애와 복구 | 변경 전 준비 실패는 기존 DNS를 유지하지만, 만료된 차단을 안전하게 제거할 수 없다면 중단. 전원 상실·복구 자료 파손은 별도 위험 |
| 클라이언트 캐시 | 리졸버의 적용/철회 시각과 사용자 체감 시각은 다를 수 있음 |
| 원격 공급망 | 배포 인증·키 관리·서명·시계 신뢰와 재시작 후 anti-replay는 추가 검토 |
| 로컬 동일 계정 탈취 | 파일 소유권만으로 방어하지 못함 |

HTTPS 강제 전환·TLS MITM은 구현하지 않습니다. 공개 저장소에는 원본 사용자 질의,
비밀키·접수 내용·실제 위협 URL을 저장하지 않습니다. [보안 운영](../SECURITY.md)을 따릅니다.
