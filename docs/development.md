# 개발·검토 규칙

- GitHub `main`의 소스·테스트를 기준으로 작업합니다. 기록을 수정할 때는 변경 전 HEAD와 원래 부모를 확인하고 다른 팀원의 변경을 덮어쓰지 않습니다.
- 코드·테스트·실행 명령은 GitHub, 일정·담당 수락·미확정 결정은 Notion에서 관리합니다.
- 제안을 팀 합의로, 소스 존재를 실행 성공으로, 단위 테스트를 운영 검증으로 바꾸어 기록하지 않습니다.
- 공통 입력은 [정책 계약](../packages/policy-contract/README.md)을 따릅니다. 실제 공급자/수신자 인수는 별도 확인합니다.

## 검증 수준

| 검사 | 증명하는 것 | 증명하지 않는 것 |
| --- | --- | --- |
| baseline.yml | 저장소 구조·위험 파일명 | 서비스 안전·동작 |
| portal.yml | 정적 UI 제약·JavaScript 문법 | 실배포 TLS·신고 API |
| dns.yml | 정책/실패 주입 및 실제 로컬 dnsmasq+dig, 설치기 입력·방화벽 구성 검사 | 운영 LAN·실제 systemd/53번 설치·외부 우회·탐지 정확도 |

로컬에 dnsmasq/dig가 없으면 통합 시험은 skip입니다. `REQUIRE_DNSMASQ=1`에서는 이 환경을 실패 처리합니다.
검토자는 정상·반례·철회·복구 결과와 **실제로 실행한 소스 SHA**를 함께 확인합니다.
외부 서비스·DB·ML 도입은 필요성, 실패 경계, 운영 부담을 먼저 설명합니다.
