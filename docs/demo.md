# 시연·실험 계획 (실행 결과 미첨부)

## 안전한 실험

1. 격리 VM의 OS/리졸버 버전·설정 및 대상 DNS 리스너·클라이언트 네트워크를 기록합니다.
2. 통제된 실험 이름에 대해 **정책 비활성 기준 응답**을 먼저 확보합니다. `.test`는 특별 용도라 NXDOMAIN이 원래 응답일 수 있습니다.
3. 정책 승인·버전·정규화·EXACT 범위를 검증하고, 정책 적용 후 A/AAAA/하위 이름 및 정상 질의를 비교합니다.
4. 정책 철회·캐시 만료 및 무효 정책 재적용 시 이전 정상 상태를 보존하는지 확인합니다.
5. 정적 안내 홈·BLOCK·WARN 페이지를 로컬에서 시연하고, 94점/72점이 **원본 UI의 시연 값**임을 보여 줍니다. WARN의 계속 방문 버튼은 설명 대화상자만 열며, 오탐 신고는 **서버 전송이 아닌 복사 가능한 초안**입니다. **실제 HTTPS 포털**을 주장하려면 팀 도메인의 정상 TLS 인증서·신고 API를 별도로 검증해야 합니다. 피싱 HTTPS 원래 탭이 안내 HTML로 자동 변하는 장면을 주장하지 않습니다.
6. 실패·과차단·우회 조건을 숨기지 않고 데이터/기능의 한계로 설명합니다.

**데모 체크:** 커밋 SHA, 설정/정책 SHA, dig 원문/정책 로그, 클라이언트 DNS 경로, 날짜·시간, 오류 복구 결과, 포털 주소/인증서, 검토자.
