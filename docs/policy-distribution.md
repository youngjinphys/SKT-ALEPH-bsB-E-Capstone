# 서명된 원격 정책 배포

**현행 정본:** [원격 정책 서버 → 사설 DNS 운영 가이드](remote-policy-deployment.md)

`apps/policy-sync/`는 독립적인 **Ed25519 서명·검증, HTTPS Pull, 장치 ID/시퀀스/만료 검사, root 적용** 모듈입니다. 원격 위험 데이터는 DNS 질의 처리 중 조회하지 않습니다.

정책 배포는 다음 순서를 준수합니다.

1. 신뢰 출처의 URL 후보를 수집하고 Google Safe Browsing으로 검증합니다.
2. 사람이 도메인 전체 차단 범위와 정당성·만료를 검토한 뒤 **완전한 정책**을 생성합니다.
3. 별도 비특권 서명자가 개인키로 서명합니다. 개인키는 DNS·공개 웹 서버에 배포하지 않습니다.
4. 원격 관리자만 `python3 -m policy_server promote`로 **서명·시퀀스·차단 철회**를 검증해 원자적으로 공개합니다.
5. LAN DNS의 fetch/apply 서비스가 검증된 정책만 기존 `system_dns.py publish` 경로에 반영합니다. 동일 시퀀스 재수신 시에도 `system_dns.py attest`로 실제 DNS 정책·응답·전용 방화벽 상태가 일치하는지 확인합니다.

**DNS 적용 내구성:** 루트 `policy-sync apply`는 서명과 만료를 검증한 뒤
`pending-apply.json`을 **게시 전에** 영속화합니다. DNS 게시가 성공해야
`applied.json`의 시퀀스를 확정합니다. 게시 후 기록 실패는 동일 서명 정책으로
재시도하고, 받은 파일이 이미 더 최신인 경우에는 미완료 정책 또는 이전 정책이
실제로 작동 중인지를 읽기 전용으로 확인한 경우에만 진행합니다. 둘 다 확인할 수
없으면 저널을 보존하고 중단합니다. **저널이나 시퀀스 워터마크를 임의 삭제하면 안 됩니다.**

**주의:** 단순 `cp`/`mv`로 `current.json`을 직접 덮어쓰는 옛 게시법은 사용하지 않습니다. 게시자 워터마크 및 삭제 승인 검증을 우회하기 때문입니다. 모든 설치 스크립트는 기본 미리보기이며 `--apply`가 필요합니다. 원격 API 장애·서명 실패 시 새 정책 적용을 거부하며 기존 규칙 만료를 연장하지 않습니다.

실행 예시와 NGINX TLS 설정은 배포 가이드 한 곳에서 유지합니다.
