## 의도적으로 유지한 보안 경계

1. 정책 엔진의 EXACT 결과는 실행 제안이며 SUBTREE DNS 차단 정책에 자동 승격하지 않는다. 점수 제공자를 인증하지 않는 로컬 `risk_adapter`도 운영 정책에 자동 연결하지 않는다.
2. 위협 URL과 GSB 데이터는 신뢰된 기존 수집·전달 계정에서 생성되어야 한다. 콘솔은 파일 내용의 구조·해시 일관성만 다루며 제공자의 실제 발신자 인증이나 리뷰어의 신원을 암호학적으로 증명하지 않는다.
3. ROOT 발행과 Ed25519 서명은 별도 사용자/시스템에서만 실행한다. 사용자 요구인 'GUI 제어'를 무제한 원격 셸 권한으로 해석하지 않는다.
4. 서명 게시 파일을 읽는 기능은 원격 TLS 전송, DNS 노드의 실집행, 차단 효과에 대한 증빙이 아니다.
5. 개인정보·원본 URL·토큰·서명 개인키를 대시보드나 코드 저장소에 노출하지 않는다.

## 남는 위험·과제

- 독립적인 DNS 노드 적용/활성 정책 검사 경로: 서명된 읽기 전용, 지연/시각/장치/시퀀스/해시 포함 영수증과 실 단말 질의 검증이 필요하다. 단순한 `applied.json` 복제는 운영 DNS가 살아 있다는 증명이 아니다.
- 조직/개인별 운영자 권한: 단일 토큰은 다중 사용자 RBAC/SSO, 보안 감사자 분리, 강력한 회수 기능이 아니다. 멀티 사용자 운영 전에 별도 인증 게이트 필요.
- 승인 무결성: 사람이 기입한 리뷰어 식별명과 비키드 SHA-256은 승인자 서명이 아니다. 서로 다른 계정에서 리뷰·서명을 독립 확인해야 한다.
- 공급 주기: 짧은 GSB 증거 만료와 분리된 수동 서명/배포 지연으로 인한 연속 보호 공백. 유효성을 연장하지 말고 갱신·검토 절차를 운영적으로 개선해야 한다.
- 운영 인수: HTTPS 프록시, 실제 로그인/권한, 실제 공개 피드와 기기, UDP/TCP DNS, 재부팅/서비스 충돌, DNS 캐시/DoH/VPN/IPv6 등의 현장 검증 미완료.
- 성능/고가용성: 표준 라이브러리 HTTP 서버는 루프백 또는 좁은 관리 채널의 단일 운영자에 적합하며 인터넷 전면에 직접 노출하기 위한 다중 사용자 고가용성 제어면이 아니다.
- 디자인 QA: 정적 HTML/스크립트 구문, DOM 요소 계약과 응답 경계는 자동화해 검증할 수 있으나 실제 브라우저 시각 스냅샷·스크린 리더 검증과 실장치 테스트는 별도다.
