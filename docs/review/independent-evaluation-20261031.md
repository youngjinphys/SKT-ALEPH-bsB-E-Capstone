# 차별성 재검토와 실행 계획 — 2026-10-31

이력 정리 기준: `bdb1abf813dcca443074f476bd23b0d3ece91e3d` 이후의 구현 전체. 이전 답변의 10/29 기준과 다르다. 본 검토는 소스·공식 자료 대조 및 자체 격리 재실행이지 제3자 보안 인증이나 독립 위협 정답 평가가 아니다.

## 유지할 결론과 수정할 주장

Protective DNS·기본 브라우저 보호·공공–민간 협력은 선행 기술이다. 기술 부재의 증명이나 특허 신규성 조사를 수행하지 않았으므로 “어떤 독창성도 없다”로 확대하지 않는다. 주장 가능한 기여는 작은 관리망을 위한 정책 신뢰·집행·철회 경계를 공개 코드와 재현 가능한 반례로 명시하는 공학적 구현이다. 제품 우월성·피해 감소는 미입증이다.

최신 코드는 원격 수집·리뷰 파일·정책 생성·서명·게시·두 서버 설치 스크립트와 중단 복구를 포함한다. 10/29의 미구현 설명을 그대로 사용하면 안 된다. 원격 승인/이의신청 API·독립 심사·실운영 인수는 이와 별개다. 이미 만료된 미완료 DNS 적용의 안전한 중단도 자율 복구 완료로 소개하지 않는다.

## 이전 평가에서 빠진 통제

| 문제 | 보완 |
|---|---|
| 예제 upstream `9.9.9.9`를 일반 DNS로 간주 | Quad9도 위협 차단을 수행한다. 실험의 무필터 대조는 통제된 양성 upstream으로 고정한다. ALLOW는 upstream 차단을 해제하는 명령이 아니다. |
| 브라우저와 DNS만 비교 | 동일 목록·장비의 원시 dnsmasq/BIND RPZ 기준선을 별도로 둬 집행/운영 효과와 위협정보 품질을 분리한다. 현재 BIND 비교 실측은 없다. |
| Safe Browsing 확인 후보를 정답으로 다시 사용 | Chrome과 신호가 겹치는 선택·라벨 순환이다. 독립 판정, 같은 관측시각, 도메인/캠페인 분할 없이 추가 탐지 우위를 계산하지 않는다. API 결과와 브라우저 동작도 동일하다고 가정하지 않는다. |
| NOERROR 또는 처음 기대 응답을 복구로 계산 | 실제 주소까지 대조한다. timeout/SERVFAIL은 차단 성공이 아니며 실패를 분모에서 빼지 않는다. 지속적 단말 복구와 서버 수락은 다른 지표다. |
| 서명·테스트 수를 안전한 운영으로 확대 | 서명은 출처·무결성이지 악성 판정의 진실성이 아니다. 게시·수신·root 적용·DNS ACK·캐시·사람 구제를 분리한다. |
| 짧은 만료를 무조건 안전하다고 판단 | 갱신 중단 시 오차단 해제와 보호 공백의 교환관계다. 목록 수집, 검토 인력, 서명, pull 주기, rule expiry, DNS TTL은 서로 다른 시간이다. |

## 실행 계획과 인수 조건

1. 실패를 숨기지 않는 결과 집계 6개 회귀시험을 먼저 작성한다. 미구현 상태의 실패를 확인한 뒤 `scripts/evidence_lab.py`를 구현한다.
2. 비특권 loopback에서 통제 upstream → 정상/차단/철회 정책, 실제 Ed25519·HTTPS 수신·재검증 → Agent → dnsmasq를 연결한다. A/AAAA×UDP/TCP와 정상 형제·하위 이름·CNAME 반례를 원문 응답과 함께 JSON으로 남긴다.
3. CI에서 같은 실험을 실행하고 실패 시에도 JSON을 로그에 출력한다. 모든 시도 수와 실패 수를 보고하며 성능 수치는 환경/모집단과 함께 해석한다.
4. 웹의 홈·캡스톤 설명에 기존 기술/구현/실측/미검증을 구분한다. 실시간 탐지·협약·운영 성능으로 보이는 표현을 줄이고 비교 방법과 원문 근거를 연결한다. 로그인과 기존 발표 조작은 유지한다.
5. 최종 트리와 테스트를 확인한 뒤 기준 커밋의 자식인 단일 커밋으로 이력을 정리한다. 원격 HEAD가 바뀌면 강제 갱신하지 않고 재검토하며, 이력 압축 전 CI는 압축 후 CI의 대체물이 아니다. 웹 배포와 코드 SHA도 각각 검증한다.

## 실행과 해석

```sh
python3 -m unittest discover -s tests/evidence -v
python3 scripts/evidence_lab.py --rounds 3 --output /tmp/aleph-evidence-new.json
```

Linux 비특권 계정, Python 3.11+, dnsmasq-base/dnsutils/python3-cryptography가 필요하다. 스크립트는 loopback 고포트·임시 디렉터리만 사용하고 기존 출력 파일을 덮어쓰지 않는다. 실제 사이트·Google·외부 DNS를 호출하지 않는다. 바인딩 경쟁이나 바이너리 부재는 실패이며 건너뛰어 성공으로 표시하지 않는다.

실험은 **TLS 수신→검증→직접 Agent 호출**의 실험용 어댑터를 사용한다. root `publish/attest`, 두 장비의 systemd/nftables/재부팅, 클라이언트 캐시, 상시 가용성은 측정하지 않는다. `server_ready_ms`는 서명 직전부터 Agent 반환까지이고 운영 타이머 지연을 포함하지 않는다. 성공 질의 지연의 p95는 실패를 포함한 서비스 SLA가 아니다. 모든 시도는 별도 분모에 남는다.

CNAME이 정상 주소를 돌려주는 관측은 알려진 공백이며 정상 하위 이름이 부모와 함께 막히는 관측은 SUBTREE의 부작용이다. 이를 탐지 성공으로 집계하지 않는다. 합성 정책 정답 일치율은 실제 피싱 탐지율·오탐률·피해 감소율이 아니다.

다음 실제 운영 관문: 두 서버의 root 경로 및 재부팅/저널 중단, cold/warm cache별 지속적 정상 응답 회복, 정상 서비스 영향, 독립 운영자의 설치·철회 노동시간, 같은 목록의 RPZ 비교, 브라우저 기본 보호를 켠 paired 실제 위협 평가. 장애·미수렴 시도와 관측 종료 시각을 반드시 보고한다. 실제 위협 재방문은 별도 승인된 격리 절차 없이는 수행하지 않는다.

## 공식 근거

- [ISC RPZ](https://www.isc.org/rpz/): QNAME 등 정책·예외·배포의 선행 구현. 현재 프로젝트와의 성능 우위를 의미하지 않는다.
- [Quad9 서비스](https://docs.quad9.net/services/): 9.9.9.9의 위협 차단과 별도 서비스 구분.
- [Chromium Safe Browsing](https://www.chromium.org/developers/design-documents/safebrowsing/): Google 신호와 브라우저 검사의 관계. 독립 정답과 구분한다.
- [Google API 조건](https://developers.google.com/safe-browsing/terms): 최신성·출처·정확도 한계 및 비상업적 사용 조건. 실제 제공 형태의 약관 충족은 별도 검토해야 한다.
- [KISA 싱크홀](https://www.boho.or.kr/kr/subPage.do?menuNo=205016), [NCSC PDNS](https://www.ncsc.gov.uk/information/pdns): 국내·외 선행 운영. 비공개 철회 SLA를 기능 부재로 취급하지 않는다.
- [TLS 서비스 신원 RFC 9525](https://www.rfc-editor.org/rfc/rfc9525.html): 원래 호스트 인증서를 신뢰시키지 못하는 DNS 싱크홀 조건에서 임의 HTTPS 302를 보장하지 못한다.
