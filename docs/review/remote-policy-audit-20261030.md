## 후속 검토: 다운로드 캐시·키 폐기·시간 경계

원격 **발행자**의 이전 키 회수 처리가 안전해도, DNS 노드의 **다운로더**는 별도 코드 경로입니다. 다음 반례를 현재 소스와 같은 Git blob으로 복원한 파일에서 재현했습니다.

| 재현한 원인 | 수정 |
|---|---|
| 캐시 서명자의 공개키를 제거하면 `FileNotFoundError`가 새 HTTPS 요청 전에 발생해 정상 새 서명자의 정책도 못 받음 | 이전 캐시 검증의 키 부재는 ETag를 버리고 전체 다운로드. 새 스냅샷은 현재 신뢰 저장소로 독립 검증 |
| HTTP 요청 시작 때 유효했던 캐시가 응답 대기 중 만료돼도 304를 정상 처리 | 304 응답을 받은 시점에 원본 캐시의 서명·장치·만료를 재검증. 만료를 연장하거나 파일을 덮어쓰지 않음 |
| 요청 대기 중 이전 키를 폐기해도 304가 정상으로 보고됨 | 304에서도 현재 신뢰 저장소를 다시 확인. 폐기된 서명자는 거부 |
| `test_fetch.py` 직접 실행 시 `unittest` 미수입으로 실패 | 직접 실행 및 discovery 양쪽 검증 |

보안 범위는 정확히 구분해야 합니다. 이 문제는 **갱신 가용성과 잘못된 다운로드 성공 보고**이며, root 적용 단계의 서명·만료 검사를 이미 우회했다는 증거는 아닙니다. 수정도 새 키의 자동 신뢰, 서명 검사 생략, 재전송 기록 초기화를 허용하지 않습니다.

새 다운로드 회귀 4개는 수정 전 실패하고 수정 후 성공했습니다. 비특권 계정에서 **실제 localhost TLS·Ed25519**로 기존 9개와 함께 13개를 실행했습니다. 시계/키 변경은 HTTP 응답 도중에만 주입했습니다. 외부 API와 운영 DNS는 호출하지 않았습니다.

`test_key_rotation_apply.py`의 root 전용 4개는 새 키의 낮은 시퀀스 거부, 높은 시퀀스 수락, 미신뢰 키 거부, 만료된 미완료 적용의 안전한 중단을 확인합니다. 실제 임시 파일과 Ed25519를 사용하지만 DNS publisher/attestor는 격리된 시험 대역입니다. CI는 기존 root 적용 시험과 이 파일을 모두 실행합니다.

HTTP의 304는 저장된 **표현의 변경 여부**를 다룹니다. 정책 발행자가 서명한 유효기간·키 신뢰가 연장된다는 뜻은 아닙니다. [RFC 9111 §4.3](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.3)과 정책 검증을 다른 계층으로 취급합니다.

## 유지되는 기존 방어

DNS 질의는 로컬에서 처리하고 원격 다운로드는 별도 계정이 수행합니다. 서명·장치 ID·시퀀스·만료 검사, DNS 적용 후 확인, 같은 시퀀스의 DNS attestation을 유지합니다. attestation은 설치 정책·에이전트 메타데이터·양성 건강 응답·nftables 소유 상태의 대표 검사이지 모든 질의나 점검 사이의 변조를 보증하지 않습니다.

Google의 URL 신호를 도메인 전체 SUBTREE 승인으로 자동 승격하지 않습니다. 위험 제안의 EXACT와 집행 SUBTREE는 다른 계약이며, 기존 dnsmasq를 임의로 교체하거나 TLS MITM을 추가하지 않았습니다.

## 로컬 적용의 중단·재전송 복구와 제한

DNS 노드는 root 소유 `pending-apply.json`에 서명 시퀀스와 payload/정책 해시를 **게시 전** 저장하고, DNS 수락 후에만 `applied.json`을 확정합니다. 실제 DNS가 미완료 정책을 적용했으면 그 시퀀스를 먼저 복구하고, 직전 정책이 계속 적용 중이면 미완료 시도를 정리한 뒤 더 최신 서명 정책만 수락합니다.

**새 시험으로 확인한 잔여 경계:** 첫 정책 게시 후 로컬 영수증 기록이 실패하고, 복구 전에 그 정책이 만료되면 더 최신 정상 정책이 있어도 확인 가능한 이전 상태가 없어 중단할 수 있습니다. 저널은 보존됩니다. 이를 자율 복구 완료로 설명하지 않습니다. 운영자는 서명 원본·로컬 정책·저널·DNS 상태를 대조해야 하며, 기록 삭제나 만료 연장으로 우회하면 안 됩니다. 별도의 인수된 수동 복구 절차가 필요합니다.

이 검사는 저장 오류·서명 충돌·재시작 순서를 다룹니다. 서명 만료, root 침해, DNS/방화벽 동시 손상과 분산 장애에서 완전한 자율 복구를 보장하지 않습니다.

## 인증·신선도·가용성 한계

해시는 변경 탐지이지 출처/승인자 인증이 아닙니다. 수집 계정과 분리된 리뷰 사본 및 별도 서명자 권한이 필요합니다. 공급자 아티팩트와 리뷰를 모두 장악한 공격자, 서명키·root 침해는 이 해시로 막을 수 없습니다. source allowlist 역시 발신자 인증이 아닙니다.

OpenPhish 후보 수집 주기(약 12시간), GSB 최신성 상한(30분), 코드의 BLOCK 상한(15분)은 별개입니다. 수동 검토·서명만으로 상시 차단을 보장하지 않습니다. 자동 연장으로 숨기지 말고 운영 권한·갱신 빈도·철회 담당을 결정해야 합니다. Google의 표현식 결과가 원래 URL과 다르면 보수적으로 UNRESOLVED로 남기는 제한도 유지합니다.

새 발행 복구는 **정책 파일의 트랜잭션**입니다. 패키지 설치와 DNS+sync 전체 설치, systemd/nftables 재부팅, 실제 네트워크 단절의 자동 롤백은 별도 실증 대상입니다. 특히 상위 설치 스크립트의 후반 단계 실패까지 전체 설치가 원자적으로 복원된다고 보장하지 않습니다. 실제 API 키·HTTPS·사설 LAN과 CNAME/DNSSEC/DoH/VPN/IPv6·기존 캐시도 별도 검증해야 합니다.
