# DNS Operations 콘솔 UI/UX 개선 검토 (2026-11-03)

## 목표와 변경 범위
기존 ALEPH 색채(딥 네이비·시안), 글래스 표면, Observatory 궤도 시각 요소를 유지하면서 관제 업무의 정보 우선순위와 접근성을 강화한다. 디자인 변경의 기준은 **근거의 검증**, **정책 게시**, **DNS 노드 적용**, **LAN 전체 보호**를 혼동하지 않는 것이다. 변경은 인증·API·근거 검증·정책 서명·root 발행 경계를 유지한다.

## 실제 변경
- **헤더·메인 진입점:** 관리 화면 경로와 전용 빠른 작업 버튼을 배치한다. 인증 후 위협 검토·배포 현황으로 즉시 이동하고, 화면별 문서 제목을 갱신한다.
- **상태 스트립:** 조회 시각·관제 상태·검증 범위의 의미를 분리한다. normal의 색은 DNS 적용 성공을 암시하지 않는 중립 시안이다. 경고 및 검증 실패는 텍스트를 유지하며 구별한다.
- **데이터 카드:** 위협 검토 지표와 DNS 노드 카드를 시각적으로 분리한다. 표시값은 기존 API의 실제 응답에서만 가져오고 모의/임의 데이터를 생성하지 않는다.
- **정책 파이프라인:** 4단계를 실제 탐색 버튼으로 만들되 4단계는 서명된 게시 / DNS 적용은 별도 확인으로 표시한다. 승인/서명/root DNS 권한을 부여하지 않는다.
- **위협정보 갱신:** OpenPhish·GSB 수집 상태 RUNNING 중에만 무한 진행 신호를 사용한다. 진행률이나 외부 API 성공을 추측하지 않는다.
- **노드 상태:** 기존 good/warn/bad 분류에 따라 카드 테두리만 강화하고 상태 텍스트와 LAN 미검증 고지를 유지한다.
- **반응형·접근성:** 좁은 화면의 고정형 가로 탐색, 2열/1열 카드 배치, 키보드 포커스 링 및 reduced motion/transparency, forced-colors, increased-contrast 모드를 고려한다.
- **의존성:** 외부 폰트·스크립트·이미지/CDN을 추가하지 않았고 textContent 기반 출력과 기존 CSP를 유지한다.

## 검증과 남은 범위
기존 tests/policy_server/test_console.py의 HTML ID 일치·인증·CSRF·CSP 및 관련 렌더 자산 검사에 디자인·접근성 계약을 추가한다. GitHub Actions는 Python 테스트와 Node --check를 실행한다. 실제 운영 주소의 브라우저 스크린샷 시각 검증은 별도로 수행해야 한다.
360/390/768/1024/1440px별 브라우저 렌더, 200% 확대·OS 고대비·키보드, 운영 네트워크 장애와 정책 만료 상태에서의 문구 줄바꿈은 현장 검증 대상이다.
